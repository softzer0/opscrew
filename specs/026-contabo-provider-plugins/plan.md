# Implementation Plan: Contabo, opening with the contract for cloud server providers

**Branch**: `main` | **Date**: 2026-11-11 | **Spec**: [spec.md](spec.md) | **Research**: [research.md](research.md)

## Summary

Everything OpsCrew knows about one cloud server provider moves into one package that exports one
definition, typed by a versioned contract in `@opscrew/contracts`. A small registry package lists
the built-in definitions, validates them and is the only place consumers read provider facts
from. Hetzner and DigitalOcean move first, with byte-identical output. Then the consumers learn
the few things Contabo needs that the other two never did: removal by cancellation, a setup fee
and minimum term, snapshots included up to a count, no resizing, taking over a server the state
lost, and credentials that come as a set of four. Contabo is then written as the third
definition, with its own connector (OAuth2, typed client) and HCL module (`contabo/contabo`).
Installing provider packages is 028's.

## Technical Context

- TypeScript monorepo (`packages/*`, `packages/connectors/*`), OpenTofu/Terraform, the bundled CLI
  (tsup, every `@opscrew/*` package inside).
- Builds on:
  - 002/004: the VPS seam (ADR 0006), `vpsConnector` and `providerProfile` in
    `agents/src/providers`;
  - `PROVIDER_TEXT` in `iac-templates/src/providers.ts` and the vendored modules (generated by
    `iac-templates/scripts/gen-modules.ts`);
  - SecOps's provider table (`secops/src/policies/plan.ts`) and token rules
    (`secops/src/rules/secrets.ts`);
  - 024's whole-server snapshots (`ServerSnapshotApi`); 023's retarget; 018's several servers
    (WireGuard, no provider networks); 025's user tokens.
- Research R1 is the map of every place a cloud provider's facts live today.

## Constitution Check

- **I (gate):** unchanged. Contabo's servers, firewall and SSH key go through the IaC engine's
  approved apply. A destroy's shutdown is a typed-adapter call listed in the same approved plan,
  as the snapshot before a teardown is today. Taking over a lost server is an `import` block in
  the plan, shown and approved by its hash.
- **II (ownership):** Contabo's HCL module is vendored like the others, readable, with no remote
  source.
- **III (dual engine):** the `contabo/contabo` provider is on both registries (R2). The module
  passes `validate` under both engines in the existing module tests.
- **IV (secrets):** the four credentials are read only by the connector and the engine's
  environment, registered with the redactor on read, and never in tfvars, state, the server or
  CI. Contabo's provider reads them from `CNTB_OAUTH2_*` itself, so they never enter HCL.
- **VI (contracts):** one new contract, `CloudProviderDefinition`, owned by `@opscrew/contracts`,
  written by the lead with ADR 0029. `ComputeOffer`, `ProviderExtras` and `AppServer` gain
  optional fields. ADR 0029 supersedes ADR 0006's seam.
- **VII (tests):** a shared conformance test runs for every definition. The existing snapshot
  tests prove byte-identical output for Hetzner and DigitalOcean. Contabo's connector is tested
  with injected `fetch` fakes; the live pass runs once (R5).
- **X (lean):** no new runtime dependency. The Contabo client is `fetch` plus zod.

## Design

### 1. The contract (`@opscrew/contracts`, `provider.ts`; lead)

`CloudProviderDefinition`, `contractVersion: 1`. Only plain data, `RegExp`s and functions; no zod
schema, class instance or import from another OpsCrew package crosses it. Region keys are
strings, which the registry checks against `RegionSchema`. Its parts, each taken from where it
lives today (R1):

- **Identity and wording:** `id`, `displayName` ("Hetzner Cloud"), `name` ("Hetzner"),
  `serverNoun`, `summaryNoun`, `titleSuffix`, `console`, `consoleUrl`, `accountUrl`, and the
  interview option's label and hint.
- **Credentials:**
  - `envVars` and `mode` (`any`: the first one set, as Hetzner and DigitalOcean; `all`: every
    one needed, as Contabo's four);
  - `description`, `scopes`, `createUrl`;
  - the init check's help text (`fix`, `scopeNote`);
  - the SecOps token rules (pattern, group, title, description);
  - the variable prefixes `detect` treats as the provider's;
  - the 403 pattern that blames this provider's token (`apiPattern`).
- **Connector:** `connector(deps) => VpsConnector`. Its `deps` are env, fetch, redactor, version,
  sleep and now, as `vpsConnector` passes today.
- **Regions:**
  - `locations` (per region, in order of preference) and `locationNames`;
  - `regionNotes`;
  - the coordinates of each location (from `design/delay.ts`).
- **Pricing and lifecycle:**
  - `currency` and `defaultImage`;
  - backups: `backupPercent`, `providerBackups`, `backupsOutliveServer`;
  - `snapshots`: `{ kind: "per-gb" }` or `{ kind: "included" }`, the limit per offer coming from
    the catalog;
  - `serverSnapshotsOutliveServer`;
  - `deleteProtection`;
  - `resize` (true when a size change applies in place);
  - `removal`: `"delete"`, or `"cancel-at-term-end"` with a `minimumTermMonths`;
  - the error patterns `unavailable` and `serverLimit`.
- **Terraform:**
  - the provider requirement (local name, source, version);
  - `serverResourceType`, `firewallResourceType` and `mirroredAttributes`;
  - `module`: its name and files, without `cloud-init.yaml.tftpl`, which iac-templates adds to
    every server module;
  - the variable descriptions, `moduleArguments(call)` and `extraShared`;
  - the runbook texts (today's `ProviderText.runbook`, plus `serverLabel`).
- **SecOps:** today's `ProviderChecks` row: the server and firewall types, the firewall rules
  reader, `attached`, and the texts.
- **Destroy:** today's `destroyTexts` for the provider.

`ModuleCall` and `ProviderRequirement` move into the contract. `ComputeOffer` gains `setupFee?`
and `includedSnapshots?`. `ProviderExtras` gains `snapshotsIncluded?`. `AppServer` gains
`cancelledUntil?` (an ISO date). `ProviderId` and `VpsProviderId` stay literal unions; the lead
adds `contabo` to them with plan-schema's enums in wave 4.

### 2. Packages

- `packages/connectors/hetzner` and `digitalocean` move to `packages/providers/hetzner` and
  `digitalocean`, renamed `@opscrew/provider-hetzner` and `@opscrew/provider-digitalocean`. Each
  then exports its connector (as today) and `definition`. The HCL module moves from
  `iac-templates/modules/<module>` to `packages/providers/<id>/module/`.
- `packages/providers/contabo`: `@opscrew/provider-contabo`.
- `packages/providers/registry`: `@opscrew/providers`.
  - `CLOUD_PROVIDERS`, the definitions in order: Hetzner, DigitalOcean, Contabo.
  - `cloudProvider(id)`, `isCloudProvider(id)`.
  - Every definition is validated at load (zod: shape, `contractVersion`, region keys), with a
    plain error naming the provider and the part.
  - A conformance test that runs for every built-in definition. It lives in the registry, since a
    provider package can't depend on the registry, which depends on it.
  - A test that the registry's ids equal `CloudProviderSchema`'s options in plan-schema.
    plan-schema keeps its literal enums, because a provider package uses plan-schema's types and
    a reverse import would be a cycle.
- Dependencies point one way: provider packages → contracts and core; registry → providers;
  agents, iac-templates, secops, detect, mcp-server and cli → registry. No provider package
  imports iac-templates, agents or plan-schema at runtime.
- The modules are generated by a root script, `scripts/gen-provider-modules.ts` (lead). It embeds
  `packages/providers/*/module/**` into each provider's `src/generated/module.ts`, and a test in
  each provider fails when that file is stale. iac-templates' generator keeps the non-provider
  modules (Cloudflare) and the check script. The renderer writes a provider's module from its
  definition, plus the shared cloud-init, to the same paths as today.

### 3. The consumers (byte-identical for Hetzner and DigitalOcean)

- **iac-templates:**
  - `PROVIDER_TEXT`, `cloudTarget` and `infra/servers.ts`'s `SHARED_RESOURCES` read the
    definitions;
  - the module writer takes provider modules from them;
  - the module validate tests iterate the registry.
- **agents:**
  - `providers/profiles.ts` builds `ProviderProfile` for each cloud provider from its definition
    (own, Portainer, this computer and the serverless profiles stay);
  - `vpsConnector` calls `definition.connector`;
  - `design/wording.ts`, `design/delay.ts`, `provision/plan-apply.ts`'s `PROVIDER_API`,
    `destroy/texts.ts`, `destroy/storage.ts`'s console names and `init/checks.ts`'s help read
    definitions;
  - the interview's options list the registry.
- **secops:** the provider table and the token rules come from the registry.
- **detect:** the provider prefixes come from the registry.
- **mcp-server and cli:** the placement enum, `retarget`'s server list and flags, the interview's
  next step and the server text list the registry.
- The object-storage providers (r2, hetzner, digitalocean, garage) stay as they are. They are
  bucket providers, a separate choice, and Contabo's object storage is out of scope.
- `core/redact.ts`'s token patterns stay: they are a list of known secret formats, not provider
  branches.
- Wave 2's diffs touch no `__snapshots__` file and no test expectation beyond imports; reviewers
  check that.

### 4. What Contabo needs from the consumers (wave 3, generic)

1. **Removal by cancellation** (`removal: "cancel-at-term-end"`):
   - Destroy's plan and typed confirmation say the server is billed to the end of its term and
     that its disk and snapshots go then.
   - The approved plan lists the shutdown (`servers.powerOff`) before the IaC destroy. The
     destroy's `contabo_instance` delete is the provider's cancel.
   - After the apply, OpsCrew reads the instance (`findAppServers` → `cancelledUntil`) and shows
     and audits the end date.
   - No provider snapshot is offered when `serverSnapshotsOutliveServer` is false. OpsCrew's data
     snapshot, with its off-server copy, is offered instead when the server holds data (024).
2. **Prices:**
   - design, cost and advise add the setup fee once, state the minimum term, and price snapshots
     as "included, up to N";
   - an offer with no live price says so with the table's date (already the static path);
   - `resize: false` makes design's and advise's size changes refuse, with "move to a new
     server" (023's retarget) named as the way.
3. **Taking over a lost server:**
   - Before provision's plan, `findAppServers(app)` is compared with the state. A running server
     with the app's name that the state lacks is shown and imported with an `import` block.
   - A cancelled one (`cancelledUntil`) is never taken over: the plan says a new server is
     bought.
   - This is generic for all three providers: it only appears when such a server exists.
4. **Credentials as a set** (`mode: "all"`): `init`, provision's credential check,
   `providerFromTokens` and rotate's user-token list read every variable of the set and name the
   missing ones.
5. **Snapshots up to a limit:** `snapshot --server` refuses at the offer's `includedSnapshots`,
   naming the oldest to delete. A restore of a snapshot that isn't the newest says first that
   the newer ones go.

### 5. Contabo (wave 4)

- **The client** (`src/client.ts`):
  - OAuth2 password grant against the Keycloak token URL;
  - the token cached until it expires, renewed once on a 401;
  - an `x-request-id` (UUIDv4) on every call, and zod on every answer;
  - the error bodies mapped to plain English (402 = "a paid service is needed", 422 on cancel =
    "not created through the API; cancel it in the Customer Control Panel");
  - the four values registered with the redactor on read.
- **The connector:** `verifyCredentials` (a token, then a read of the instances); a static catalog
  (`static-prices.ts`: Cloud VPS 4, 6, 8 and 12, monthly rate, setup fee, included snapshots,
  dated); and `ServerSnapshotApi` over the instances and snapshots API:
  - `findAppServers` by display name and OpsCrew's tag, with the cancel date;
  - `snapshotServer`, `listSnapshots`, `deleteSnapshot`;
  - `rebuild` = revert;
  - `powerOff` = shutdown and wait; `powerOn` = start.
- **The module** (`module/contabo-vps`):
  - a `contabo_secret` (ssh), shared like Hetzner's key;
  - a `contabo_instance`: product, region, image looked up by name, `period = 1`,
    `ssh_keys = [secret]`, `user_data` from the shared cloud-init, `default_user = "root"` with
    cloud-init making `deploy` and closing root login as elsewhere, and `display_name` = the
    app's name;
  - a `contabo_firewall` with the same rules as Hetzner's, attached by `instance_ids`;
  - `lifecycle.ignore_changes` on user data, image and SSH keys, as on the others.
- **Regions:** eu-central → EU; eu-north → EU, with a note that Contabo has no Nordic location;
  us-east → US-east; us-west → US-west; ap-southeast → SIN.
- **Texts:** runbook, destroy, init help (Customer Control Panel → Account → Security), the
  interview option ("Contabo, cheaper servers, monthly contracts").

## Decisions (lead, 2026-11-11)

1. **Providers live in `packages/providers/<id>`**, named `@opscrew/provider-<id>`, as 028's AWS
   package will be.
2. **plan-schema keeps literal provider enums**, with a test against the registry. A derived enum
   would make plan-schema import the providers, a cycle.
3. **First-boot setup stays core's:** iac-templates adds the shared cloud-init to every provider
   module, so a provider never ships its own copy.
4. **Object storage stays outside the contract** in 026 (bucket providers are a separate choice).
   It joins when a cloud provider's own storage is added.
5. **Monthly terms only:** the cheaper 12- and 24-month rates are not offered, because a removal
   would then bill for up to two years.
6. **Contabo's firewall is managed by Terraform:** issue #56 hit only instances recreated several
   times. The spike and the live pass prove it. The fallback, should they fail, is the
   own-server host firewall (ufw with the `DOCKER-USER` filter), decided then.
7. **Taking over a lost server is generic**, not Contabo's alone: a timed-out create can leave one
   at any provider.
8. **The destroy shuts the Contabo server down** before cancelling. The user can still start it in
   Contabo's panel until the end date; the guide says so.
